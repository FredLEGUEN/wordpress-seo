Comparer les résultats de la période N avec ceux de la période N-1 (mois, trimestre, année), c'est l'analyse la plus demandée en entreprise : « Fait-on mieux que l'an dernier ? ». Et pourtant, presque personne ne sait la réaliser correctement dans Excel.

Dans cette formation, vous allez apprendre, étape par étape, la méthode professionnelle pour construire un tableau de bord dynamique qui affiche côte à côte :

  • les ventes de la période précédente (N-1) ;
  • le pourcentage de variation entre les deux périodes.

Le tout sans aucune formule complexe dans vos feuilles de calcul : les calculs sont réalisés par Power Query et Power Pivot, les deux outils intégrés à Excel que cette formation vous fait découvrir en pratique.

📚 Section : Préparer et charger vos données

Leçon 1 — Étape 1 : Présenter vos données de façon structurées aperçu gratuit

Avant de voir comment écrire les formules, il est indispensable d'avoir des données structurées.

En effet, si vos tableaux de données ne sont pas construits tel qu'attendu par Power Pivot (l'outil qui va faire les calculs), jamais vous obtiendrez un tableau de bord dynamique pour comparer deux périodes.

Un tableau de données structuré doit présenter les données « brutes » (raw data en anglais) c'est-à-dire

  1. Sans colonne vide
  2. Sans ligne récapitulative par mois par catégorie de produits ou autres
  3. Chaque colonne présente un type de données

Votre tableau de données doit présenter toutes les données unitaires, comme le détail de chaque vente, pour chaque journée. C'EST INDISPENSABLE.

  • C'est ce que l'on appelle en informatique des données granulaires (dérivées du mot grain).
  • Tout comme un grain, il est très difficile de le diviser mais en les combinant, nous obtenons des produits plus élaborés (farine, pain, gateau, tout ça à partir d'un grain de blé)
  • En informatique c'est la même chose, si vos données présentent le niveau de détail le plus fin, il sera plus simple ensuite de demander à l'ordinateur de faire tous les types de calculs que vous souhaitez à partir de ces données granulaires.

Ce type de document n'est pas à utiliser à cause des lignes de calculs par mois (ligne 8, 12, 16, 17)

  • Ce qu'il faut faire, c'est conserver uniquement le détail d'une facture par ligne.
  • Pas de regroupement par client ou par mois par exemple ⛔

C'est comme cela qu'un ordinateur est conçu pour traité les données.

Leçon 2 — Chaque colonne doit contenir le même type de données aperçu gratuit

L'autre erreur souvent commise c'est de vouloir présenter une même donnée mais sur plusieurs colonnes 😱😱

Par exemple ici, nous avons une présentation d'un tableau des résultats du chiffre d'affaires de nos magasins où chaque mois est sur une colonne différente (A NE JAMAIS FAIRE ⛔)

La seule façon de bien travailler avec un logiciel comme Excel, c’est de ranger ses données par nature dans une seule et même colonne

  • Une colonne pour le nom du magasin
  • Une pour le poste de dépense
  • Puis, la date
  • Et une dernière pour le montant des ventes

Seulement 4 colonnes, et forcément, un très grand nombre de lignes.

Et c'est justement le travail d'un ordinateur. Quand les données d'un même type sont dans une seule colonne, les calculs sont extrêmement rapides, peu importe le nombre de lignes. Alors qu'à l'inverse, comparer des colonnes c'est extrêmement complexe à coder.

Leçon 8 — Ouvrir le modèle de données dans Power Pivot

Quand vous cliquez sur la première icône Gérer, vous voyez une grille qui ressemble avec Excel, mais qui ressemble seulement.

En fait, en chargeant vos données, vous transférez vos données dans un moteur dédié aux calculs de masse (son nom c'est Vertipaq).  Les principales différences avec Excel sont

  • Les données sont en lecture uniquement (mise à jour des données impossible)
  • Pas de limitation du nombre de lignes
  • Optimisation des données automatique lors du chargement dans le modèle de données.
  • Les onglets sont appelés des Tables
  • Les calculs sont des Mesures
  • La colonne des dates est toujours représentées avec le format Heure en plus (c'est comme ça)
  • Power Pivot contient un moteur de calcul spécifique pour le calculs des dates (D'OU LA NECESSITE DE TRANSFERER LES DONNÉES DANS POWER PIVOT)

📚 Section : La Table des Temps

Leçon 1 — Étape 4 : Création de la Table des Temps

La particularité de travailler avec Power Pivot c'est qu'il faut lui indiquer une table qui va être utilisée pour les opérations sur les Dates. C'est ce que l'on appelle une table des temps (ou table de date).

Il existe plusieurs techniques pour le faire mais la méthode à préconiser c'est de créer la table des temps dans Power Query et de la charger dans le modèle de données

Pourquoi c'est mieux de créer sa table des temps dans Power Query ? Tout simplement parce que la table n'a besoin d'être chargée qu'une seule fois dans le modèle (une fois par jour c'est suffisant). Si vous faites votre table des temps depuis Power Pivot, donc avec des mesures, votre table des temps sera reconstruite à chaque phase de calcul (pas terrible comme optimisation).

Pour faire votre Table des Temps (la démo vidéo est à la fin de la formation)

  1. Allez dans le menu Données
  2. Obtenir des données
  3. A partir d'autres Sources
  4. Requête vide
  1. Ensuite, vous allez récupérer ce fichier texte contenant la requête
  2. Dans Power Query, vous allez ouvrir l'Éditeur Avancé depuis le menu Accueil
  3. Puis, collez l'intégralité du fichier texte à la place de la requête vide

Leçon 2 — Comprendre la Table des Temps

Quand votre table de temps est chargée dans Power Query, vous voyez

  • Une première colonne avec les dates au format Date mais sans un seul jour manquant (jours ouvrés, fériés, weekend, .... rien ne doit manquer)
  • Ensuite, chaque colonne qui suit représente une partie de la date
    • Juste l'année
    • Le mois en chiffre
    • Le mois en lettre
    • Jour de la semaine
    • Jour dans le mois
    • .....


IMPORTANT : Le script fourni est construit sur une date de début et de fin figée. Dans la vidéo qui va reprendre chaque partie de la méthode, vous verrez comment déduire la date de début et de fin à partir de la date minimale et maximale du jeu de données.

Mais en conservant une date minimale et maximale figée, le projet va tout de même fonctionnée.

Pour finir, il faut de nouveau charger la Table des Temps dans le Modèle de données.

Ensuite, depuis Power Pivot, vous pouvez voir votre Table des Temps s'afficher comme nouvelle table (onglet)

Leçon 5 — Étape 6 : Lier la Table des Temps avec notre jeu de données

Dernière étape avant de passer aux mesures, il faut lier les 2 tables.

  1. Selectionner le champ de la première table
  2. Glisser le sur le champ de même type (ici date) dans l'autre table

L'opération est simple à réaliser mais si l'un des éléments suivants n'est pas respecté, la liaison est impossible

  • Type de données identiques entre les 2 tables (Date - Date)
  • L'une des 2 tables doit avoir des valeurs uniques. C'est le cas de la Table des Temps.

Si l'une de ces règles n'est pas respectées, la liaison ne peut pas se faire ⛔

📚 Section : Les mesures et le tableau de bord

Leçon 1 — Étape 7 : Créer la mesure du Total des ventes de l'année en cours

Alors une mesure, ce n'est pas la même chose qu'une formule dans Excel. Ici, il y a un peu un coté "magique" dans le sens où la mesure va s'adapter au "contexte" (je l'explique à la fin de cette fiche)

  • Une mesure s'écrit dans la partie en dessous des données dans Power Pivot. Le choix de l'emplacement de la mesure n'est pas déterminant (vous pouvez l'écrire dans n'importe quelle cellule)
  • Le nom de la mesure est séparée de la fonction par le symbole ( : ) et du signe =
  • Toutes les fonctions sont en anglais.

La mesure pour calculer les ventes de l'année en cours est très simple à écrire.

Ventes:=SUM([Total])

Alors le chiffre renvoyé par la mesure, n'est pas exploitable pour le moment (c'est la somme des 78694 lignes ; aucun intérêt)

Par contre quand nous allons utiliser cette mesure dans un Tableau Croisé Dynamique, là vous allez comprendre cette histoire de "contexte".

Leçon 2 — Étape 8 : Mettre la mesure dans un TCD

Nous allons maintenant construire un TCD en utilisant la mesure Ventes

  • Nous allons glisser depuis la Table des Temps l'année et le mois en Lettre dans la zone Ligne
  • Puis déposer la mesure Ventes dans la zone Valeur. Une mesure se distingue des autres champs par le symbole fx

Et c'est là où le principe de "contexte" prend tout son sens.

Pour chaque association Année + Mois, la mesure va demander au moteur de Power Pivot de lui retourner la somme correspondant à ce critère. Et ainsi de suite pour chaque couple Année + Mois. Cela peut sembler répétitif mais c'est comme cela que Power Pivot fonctionne.

Donc une mesure ne se comprend qu'une fois mises dans un TCD avec les critères de sélection choisi.

Leçon 3 — Étape 9 : Création de la mesure pour les ventes de l'année N-1

Ca y est ! Nous y sommes. La mesure pour récupérer le montant des ventes de l'année N-1 s'obtient avec la mesure suivante :

Ventes N-1:=CALCULATE([Ventes];DATEADD(Table_Temps[Date];-1;YEAR))

  • CALCULATE va "altérer" le résultat d'une mesure
  • Ici, nous allons "altérer" le résultat de la mesure Ventes
  • Altérer par quoi ? Par un décalage d'un an.
    • Fonction DATEADD
    • Colonne Date de la Table des Temps (obligatoirement cette colonne)
    • -1
    • Période : L'année


Et ajoutant cette mesure à notre TCD nous avons une nouvelle colonne qui donne le résultat de l'année précédente.

On voit bien sur cet exemple que le montant de vente de 2020 se reporte en colonne vente de l'année N-1 en 2021

Leçon 4 — Comprendre la mesure de l'année N-1

Alors la formule peut sembler courte et peu complexe mais elle découle de tout le travail qui a été fait précédemment

  • La fonction CALCULATE va "altérer" le résultat d'une précédente mesure
  • Le premier argument reprend la mesure des ventes que nous avons écrites précédemment
  • Ensuite, nous allons utiliser la fonction DATEADD pour créer un décalage d'une année
    • Le premier paramètre est obligatoirement la colonne Date de la Table des Temps  (c'est pour cela que nous avons besoin d'une table des temps)
    • Ensuite on retranche 1
    • Et pour finir nous indiquons la périodicité, ici l'année (YEAR), mais nous aurions pu indiquer le mois (MONTH) ou le trimestre (QUARTER)



Donc la fonction va reprendre la mesure Ventes auquel elle va appliquer un décalage de -1 année.

Leçon 5 — Etape 10 : Calculer la variation entre les deux périodes

Pour finir notre rapport, nous devons ajouter une nouvelle mesure pour faire la variation entre les 2 périodes.

La mesure est ici très simple

Var N-1:=DIVIDE([Ventes]-[Ventes N-1]; [Ventes N-1])

  • Nous aurions pu faire une simple division, mais la fonction DIVIDE permet de gérer les erreurs.
  • Si nous sélectionnons la première année de notre modèle, nous devrions faire une division par 0 avec une division => erreur
  • Mais la fonction DIVIDE a été conçu dans ce but précis.
  • Elle fait à la fois le calcul d'une division et gère les éventuelles erreurs de division par 0

Comme cette mesure retourne un pourcentage, il faut cliquer sur le symbole % dans le ruban de Power Pivot pour afficher le résultat de cette mesure sous forme de pourcentage.
